# מדריך מנגנון העדכונים (GitHub Releases)

מסמך זה מסביר איך עובד מנגנון העדכון האוטומטי של תאריכון, ומה בדיוק
צריך להעלות ל-GitHub כדי שהוא יעבוד.

**עדכון חשוב (מגרסה 0.5.2):** המנגנון עבר מהורדת קובץ ZIP "נייד" וחילוצו
הידני, להורדת **קובץ המתקין עצמו** (ה-exe שנוצר ע"י Inno Setup Compiler,
לפי הסקריפט במעטפת ההתקנה, Tarichon-Setup.iss) והרצתו במצב שקט-לגמרי.
זה פותר סופית בעיה מתמשכת של שמות תיקיות/קבצים עבריים (בפרט תיקיית
ערכות הקול) שיצאו משובשים אחרי עדכון - הבעיה נבעה מיצירת קובץ ה-ZIP
המקורי עצמו (בכלים לא-אמינים כמו "שלח אל -> תיקייה דחוסה"), לא רק
מחילוצו, ומתקין Inno Setup אמיתי לא סובל מהבעיה הזו כלל.

**עדכון נוסף (מגרסה 0.5.3):** שני קבצי ה-.csproj של האפליקציה
(`HebrewTaskbarWidget.csproj` - הוידג'ט הראשי, ו-
`HebrewTaskbarWidget.SettingsRecovery.csproj` - כלי הגישה העצמאי
להגדרות) אוחדו לשבת יחד באותה תיקיית קוד מקור פיזית בדיוק
(`src\HebrewTaskbarWidget.SettingsRecovery\`), במקום בשתי תיקיות
נפרדות כמו קודם - כדי לבטל כפילות תיקיות מיותרת. הם עדיין שני קבצי
.csproj נפרדים, שעדיין מקומפלים לשני קבצי הרצה נפרדים
(`HebrewTaskbarWidget.exe` ו-`HebrewTaskbarWidgetSettings.exe`) - אין
לזה שום השפעה על מנגנון העדכונים המתואר במסמך הזה, מלבד שינוי הנתיב
של קובץ ה-.csproj הראשי (ראו למטה).

## איך זה עובד, בקצרה

1. **בדיקה שקטה, פעם ביום:** בכל עליית התוכנה, אם עברו יותר מ-24 שעות
   מהבדיקה האחרונה (ואם ההגדרה "בדוק עדכונים אוטומטית" מופעלת - כברירת
   מחדל היא מופעלת), התוכנה שולחת ברקע (בלי לעכב או להציג כלום למשתמש)
   בקשה ציבורית ל-API של GitHub:
   `https://api.github.com/repos/<owner>/<repo>/releases/latest`
   ומשווה את הגרסה שם לגרסה המותקנת אצל המשתמש. אם יש חדשה יותר, וגם
   יש בה קובץ מתקין תקין (ראו למטה), זה נשמר בזיכרון עד שהמשתמש יפתח
   את פאנל ההגדרות.
2. **לשונית "כללי":** תמיד מציגה את הסטטוס (לא נבדק / מעודכן / "גרסה
   X.X.X זמינה"), עם כפתור "בדוק עכשיו" לבדיקה ידנית בכל רגע, ותיבת
   סימון להפעלה/כיבוי הבדיקה האוטומטית היומית.
3. **לחיצה על "עדכן":** מורידה את קובץ המתקין (עם פס התקדמות חי), ואז
   התוכנה **יוצאת לגמרי**, מפעילה תהליך עזר קטן (PowerShell, נסתר
   לגמרי מהמשתמש) שממתין שהתוכנה תיסגר, מריץ את המתקין שהורד במצב
   **שקט-לגמרי** (/VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP-) - בלי
   שום חלון, שאלה, או תיבת דו-שיח - וממתין שיסיים, ואז מפעיל את התוכנה
   מחדש - הכול תוך שניות ספורות, כמעט בלי שהמשתמש ירגיש. אין צורך
   בהרשאות מנהל: התוכנה מותקנת ממילא ללא הרשאות מנהל (PrivilegesRequired=
   lowest ב-Tarichon-Setup.iss), כך שגם ההרצה השקטה של המתקין לא דורשת
   שום אישור UAC.
4. **שימור הגדרות:** קובץ ההגדרות (`settings.json`, ערכות קול שנוספו
   וכו') נמצא כל הזמן בתיקיית `%AppData%\HebrewTaskbarWidget` - מיקום
   נפרד **לגמרי** מתיקיית ההתקנה שמתעדכנת. המתקין בכלל לא נחשף לתיקייה
   הזו, ולכן כל ההתאמות האישיות נשארות כפי שהיו, אוטומטית, בלי מאמץ
   נוסף.

## שתי נקודות שחשוב להבין - איך המתקין "יודע" מה לעשות בעדכון

### מיקום התקנה לא-ברירת-מחדל
המתקין מזהה התקנה קיימת לפי מזהה קבוע (`AppId` בתוך `[Setup]`, זהה בכל
הגרסאות - ראו Tarichon-Setup.iss) ולא לפי הנחה על מיקום. כל עוד לא
מעבירים לו פרמטר `/DIR` מפורש (ואיננו מעבירים - ראו הסקריפט שמריץ אותו
ב-`UpdateService.ApplyUpdateAndRestart`), Inno Setup עצמו משתמש
אוטומטית **באותה תיקיית התקנה בדיוק** שבה המשתמש בחר בפעם הראשונה, גם
אם היא לא `{localappdata}\Programs\Tarichon` (ברירת המחדל). זו התנהגות
מובנית של Inno Setup לכל התקנה עם `AppId` קבוע - אין צורך בשום קוד נוסף
כדי לתמוך בזה.

### שימור הגדרות אישיות וערכות קול
קטע ה-`[Files]` במתקין (ראו Tarichon-Setup.iss) רק מוסיף/מחליף קבצים
שרשומים בו במפורש (`Source: "{#MainFilesDir}\*"; ... Flags: ignoreversion
recursesubdirs createallsubdirs`) - הוא **לעולם לא מוחק** קבצים קיימים
בתיקיית ההתקנה שאינם ברשימה. מחיקה כזו קורית רק בהסרת התקנה מפורשת
(`[UninstallDelete]`), שלא מופעלת בזמן עדכון בכלל. בנוסף, קובץ ההגדרות
עצמו (`settings.json`) ממילא נמצא ב-`%AppData%` - מיקום נפרד לגמרי
מתיקיית ההתקנה שהמתקין נוגע בה - כך שהוא לא נחשף למתקין בכלל. המשמעות:
גם הגדרות אישיות וגם כל ערכת קול מותאמת-אישית שהמשתמש הוסיף (בתוך
תיקיית ההתקנה או ב-AppData, לפי המקרה) משתמרות אוטומטית בעדכון, בלי
צורך בשום טיפול מיוחד.

## מה צריך להגדיר בקוד (חד-פעמי)

בקובץ `Services/UpdateService.cs`, בראש המחלקה, יש שתי שורות שחובה
לעדכן לפני שהפיצ'ר יעבוד בפועל:

```csharp
private const string GitHubOwner = "YOUR-GITHUB-USERNAME";
private const string GitHubRepo = "YOUR-REPO-NAME";
```

יש להחליף אותן לשם המשתמש/ארגון שלכם ב-GitHub, ולשם המאגר (Repository)
שבו תעלו את הפרוייקט. **המאגר חייב להיות ציבורי (Public)** - ה-API של
GitHub ל-Releases דורש הרשאה/מפתח (Token) עבור מאגרים פרטיים, והתוכנה
לא כוללת שום מפתח כזה (וגם לא כדאי, מטעמי אבטחה, להטמיע מפתח בתוכנה
שמופצת למשתמשים).

## מה בדיוק להעלות ל-GitHub, בכל גרסה

### א. קוד המקור
מעלים את כל תיקיית `src` (ותיקיות אחיות רלוונטיות) למאגר ה-Git שלכם -
זה החלק הרגיל, הכולל.

### ב. יצירת Release חדש, עם הקובץ הנכון

בכל פעם שיוצאת גרסה חדשה (אחרי שקבעתם `Version`/`AssemblyVersion`
בקבצי ה-.csproj בהתאם), יש ליצור **Release** חדש ב-GitHub (מהעמוד
הראשי של המאגר -> "Releases" -> "Draft a new release"):

1. **Tag** - **חובה** בפורמט `vX.Y.Z` (לדוגמה: `v0.5.3`) - התוכנה
   מסירה את ה-`v` ומשווה את שאר המחרוזת כמספר גרסה. חייב להיות זהה
   (חוץ מה-`v`) למה שרשום ב-`Version`/`AssemblyVersion` בקובץ
   `HebrewTaskbarWidget.csproj` (הפרוייקט הראשי - יושב יחד עם הפרוייקט
   השני, `HebrewTaskbarWidget.SettingsRecovery.csproj`, באותה תיקייה
   פיזית, `src\HebrewTaskbarWidget.SettingsRecovery\`).

2. **קובץ המתקין (exe) - קימפול עם Inno Setup Compiler:**
   בונים את קובץ ה-publish (ראו מעטפת ההתקנה, `Guide-Installer.md`,
   להוראות המלאות), מעדכנים את `MyAppVersion` בראש `Tarichon-Setup.iss`
   לגרסה הנוכחית, ומקמפלים עם Inno Setup Compiler. הפלט (בתיקיית
   `Output`) ייקרא אוטומטית `Tarichon-Setup-X.Y.Z.exe` (לפי
   `OutputBaseFilename={#MyAppVersion}` בסקריפט) - **בדיוק** תבנית השם
   שהתוכנה מחפשת (ראו `UpdateService.InstallerAssetPattern`), כך שאין
   צורך בשום שינוי-שם ידני לפני העלאה.

   **חשוב - עבור קובץ המתקין המיועד לעדכון אוטומטי, יש לקמפל עם
   `#define IncludeDotNetRuntime false`** (גם אם עבור ההפצה הראשונית/
   ההורדה הידנית מהאתר אתם בוחרים לפעמים בגרסה הכוללת את ה-.NET 8
   Runtime המלא) - מי שכבר מריץ גרסה קודמת של התוכנה כבר יש לו את ה-
   Runtime מותקן ממילא, כך שאין טעם "לגרור" את קובץ ה-Runtime הגדול
   (עשרות מגה-בייט) בכל עדכון; קובץ ה-exe הקטן יותר גם מוריד ומתקין
   מהר יותר ברקע. אם בכל זאת נמצא Runtime חסר (מקרה חריג) - המתקין,
   גם במצב שקט, ידלג פשוט על שלב ההתקנה שלו במקום להיכשל.

   מצרפים את הקובץ הבודד הזה (`Tarichon-Setup-X.Y.Z.exe`) כ-Asset
   ל-Release - **אין** צורך לצרף שום קובץ נוסף (לא ZIP, לא Runtime
   בנפרד) למנגנון העדכון האוטומטי עצמו.

3. **תיאור ה-Release - זה בדיוק מה שמוצג בכפתור "מה חדש בגרסה זו"!**
   תוכן שדה "Describe this release" (בעמוד יצירת ה-Release ב-GitHub)
   מוצג למשתמש **בדיוק כמו שהוא** (טקסט רגיל) כשהוא לוחץ על כפתור "מה
   חדש בגרסה זו" בלשונית "כללי" - זה המקום היחיד שצריך לכתוב בו את
   רשימת השיפורים/התיקונים, אין צורך בשום דבר נוסף בקוד. מומלץ: להעתיק
   לשם את הפסקה המתאימה מ-CHANGELOG.md (רק את הכותרת+הפריטים של הגרסה
   הזו, לא את כל הקובץ), בטקסט פשוט (בלי Markdown מורכב - כותרות/רשימות
   של GitHub עצמו כן מוצגות יפה, אבל התצוגה בתוך התוכנה היא כטקסט פשוט,
   כך שעדיף לשמור על עיצוב מינימלי - למשל שורות עם "-" בתחילתן, לא
   טבלאות או תמונות). החלונית שמציגה את הטקסט הזה בתוך התוכנה נפתחת
   כעת בגודל בינוני קבוע עם גלילה פנימית, כך שאין בעיה גם ברשימות
   ארוכות במיוחד. אם משאירים שדה זה ריק, כפתור "מה חדש" פשוט לא יוצג
   בתוכנה (אין שגיאה, רק שהכפתור מוסתר).

זהו - ברגע שה-Release פורסם (לא כ-Draft/טיוטה, וגם לא מסומן כ-
"Pre-release"), התוכנה של כל המשתמשים תזהה אותו אוטומטית תוך יממה
(או מיד, אם ילחצו "בדוק עכשיו" בלשונית "כללי"). בנוסף, 5 דקות אחרי כל
עליית תוכנה (גם אם המשתמש לא נכנס בכלל ללשונית "כללי"), אם נמצא עדכון
התוכנה תציג הודעה יזומה (כמו ההודעה של אישור הפעלה מחדש של Explorer)
ששואלת אם לעדכן עכשיו - עם אישור/ביטול.

## הערות חשובות

- **שם קובץ המתקין חייב להתאים לתבנית** - מתחיל ב-`Tarichon-Setup-`
  ומסתיים ב-`.exe` (ראו `UpdateService.InstallerAssetPattern`). התוצאה
  הטבעית של קימפול `Tarichon-Setup.iss` ללא שינוי כבר תואמת את זה
  במדויק, כך שבדרך כלל אין צורך לחשוב על זה בכלל.
- אם Release מסויים **לא** כולל קובץ מתקין שמתאים לתבנית (לדוגמה, אם
  רק פרסמתם קוד מקור בלי לצרף Asset), התוכנה תזהה שיש גרסה חדשה יותר
  אך **לא תציע לעדכן אוטומטית** (כדי לא להיכשל בהורדה של קובץ שלא
  קיים) - המשתמשים יצטרכו להוריד ולהתקין ידנית במקרה כזה.
- אם אתם רוצים לפרסם גרסת Beta/טרום-שחרור בלי שהתוכנה תציע אותה
  לעדכון אוטומטי לכולם, סמנו אותה ב-GitHub כ-"Pre-release" - שדה
  `"tag_name"` שמוחזר מ-`/releases/latest` **מתעלם** מגרסאות שמסומנות
  כך (ה-API של GitHub עצמו כבר מדלג עליהן).
- מהירות ההורדה בפועל תלויה בקצב ההעלאה של GitHub Releases (בד"כ מהיר
  מאוד) ובחיבור האינטרנט של המשתמש.
- ההרצה השקטה של המתקין (`/VERYSILENT`) מדלגת אוטומטית על שורת ה-[Run]
  שמפעילה את התוכנה בסיום ההתקנה (מסומנת `skipifsilent` בכוונה, כדי לא
  להפתיע משתמש שמריץ את המתקין ידנית ובשקט מסיבות אחרות) - לכן
  `ApplyUpdateAndRestart` דואג בעצמו להפעיל את התוכנה מחדש אחרי שהמתקין
  מסיים.
